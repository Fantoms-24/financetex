## Деплой: Nitro + Vercel
- Сборка через `nitro({ preset: 'vercel' })` в `vite.config.ts`, но **только на `command === 'build'`**,
  чтобы dev остался на чистом Vite и порту 8080.
- Nitro выдаёт `.vercel/output` (Build Output API v3), а **не** `.output`.
  Поэтому из `vercel.json` убраны `outputDirectory` и `rewrites` — они ломали бы деплой.
  В `vercel.json` остались только `buildCommand`, `framework: null` и `crons`.
- Заголовок `Service-Worker-Allowed: /` для `/sw.js` задаётся через `routeRules` в `nitro()`.
  Проверено: он попадает в `.vercel/output/config.json`.

## Better Auth 1.7 — три ловушки (все исправлены)
1. `advanced.database.generateId: false` + `id text PRIMARY KEY` без DEFAULT
   → `null value in column "id"` — регистрация полностью не работала. Убрали опцию, id генерирует JS.
2. Схема 1.7 требует `account.issuer` (NOT NULL) и уникальный индекс `(issuer, "accountId")`.
   Добавили в `AUTH_TABLES` + в `HEAL_STATEMENTS` + индекс в `heal()`.
3. `signUpEmail`/`signInEmail` возвращают `{ token, user }`, **не** `{ user, session: { token } }`.
   Код ждал второй вариант → «Не получилось войти». Сделали `pickToken()` на оба формата.
   Плюс cookie подписанная (`<token>.<подпись>`), поэтому `auth.api.getSession()` не понимает
   наш bearer. Сессию читаем своим SQL по таблице `session` (`getSessionUser`),
   `normalizeToken()` откусывает подпись.

`postmaster.pid` (`SAFE_DELETE_BULK_CONFIRM_REQUIRED`). В dev и на Vercel+Neon (DATABASE_URL)
