## Пустая страница в dev — «приложение не запустилось»

Симптом: браузер открывает http://localhost:8080, тело пустое, сплэш висит навсегда.

Причина: `virtual:tanstack-start-dev-client-entry` (скрипт гидратации) отдавал **500**.
TanStack Start в dev требует React Refresh runtime: без подключённого
`@vitejs/plugin-react` модуль `/@react-refresh` не резолвится, и старт падает с
«requires the React Refresh runtime». Гидратации нет → `Shell` остаётся на
`if (!ready) return <splash>` →看起来 как пустая страница.

Плюс ловушка порядка: `react()` **обязан стоять после `tanstackStart()`**, иначе
`@tanstack/router-plugin` рубит сборку: «Plugin order error: '@vitejs/plugin-react'
is placed before '@tanstack/router-plugin'». Внутри `tanstackStart()` уже лежит
плагин роутера, и он требует, чтобы JSX-плагин шёл позже.

Итоговый порядок в `vite.config.ts`:
`tailwindcss() → viteTsConfigPaths() → tanstackStart() → react() → [nitro()]`

Диагностика: временный скрипт печатал `config.plugins` из `resolveConfig`
(роутер на 15-м месте, react на 24-м → `ORDER OK`).

## Как отличить
- `curl /@id/virtual:tanstack-start-dev-client-entry` — должен быть 200 и начинаться
  с `import { injectIntoGlobalHook } from "/@react-refresh"`.
- 500 или 0 байт на `/@tanstack-start/styles.css`, `/src/styles/app.css` — значит
  CSS не прогрет (первый запрос) либо упал плагин.

## Настоящая причина пустой страницы: нет shellComponent

Открыли приложение — белый лист. Нашли вторую, более глубокую причину:
SSR отдавал **голый фрагмент** — без `<!DOCTYPE>`, `<html>`, `<head>`.
Ни viewport, ни `<link rel="manifest">`, ни подключённого CSS.

**Причина:** в TanStack Start 1.168 сервер сам не рисует документ. Оболочку
даёт `shellComponent` на корневом роуте. В `react-router/dist/esm/Match.js`:

    return jsxs(route.isRoot ? route.options.shellComponent ?? SafeFragment : SafeFragment, ...)

Без него — `SafeFragment`, то есть ничего. `DOCTYPE` не встречается ни в
`react-start`, ни в `start-server-core`, ни в `react-start-server` — это
подтверждает, что документ целиком на совести приложения.

**Правка** (`src/routes/__root.tsx`): добавили `shellComponent: RootDocument`
и импортировали `HeadContent` + `Scripts` из `@tanstack/react-router`:

    function RootDocument({ children }) {
      return (
        <html lang="ru">
          <head><HeadContent /></head>
          <body>{children}<Scripts /></body>
        </html>
      )
    }

`HeadContent` сам подтягивает meta/links/styles из `head()` роутов,
`Scripts` — скрипты из SSR-манифеста. В inline-стиль добавили
`html{background:#f3eee4}` — чтобы не было белой вспышки до загрузки CSS.

**Проверка:** headless Chrome
`chrome.exe --headless=new --dump-dom --virtual-time-budget=8000` —
в DOM виден рабочий экран входа (Логин / Пароль / «Без собаки — добавим
@chekagent.app сами»), классы `sheet`, `receipt-card` на месте.

**Урок:** smoke-тест по кодам ответа этот баг не ловил — 200 был и на пустой
странице. Дописали в `scripts/smoke-vercel.mjs` проверки самого документа:
DOCTYPE, `lang="ru"`, head, viewport, theme-color `#f3eee4`, manifest,
apple-touch-icon, stylesheet. Теперь 11 роутов + 8 проверок документа → SMOKE OK.

Прогон после правки: `tsc --noEmit` чисто, `npm run build` 13.4 с,
`.vercel/output` с preset vercel, smoke OK, клиентский граф 122 модуля без битых.

## Cookie: SameSite=None без Secure — отказано браузером

После починки `shellComponent` приложение загрузилось, форма входа
отрисовалась — но при сабмите красная плашка `SameSite=None cookies must
have the Secure attribute`.

**Корень.** В `src/server/auth.ts`:

    defaultCookieAttributes: { secure, sameSite: 'none' }

`secure` вычисляется по `prodUrl.startsWith('https://')` и в dev `false`,
а `sameSite: 'none'` стоит жёстко. В `src/server/functions/auth.ts`
`putCookie` ровно такая же история: `secure: isSecure()` плюс
`sameSite: 'none'`. Получается `SameSite=None; Secure=false`, что
браузер тихо выкидывает, а в консоль пишет предупреждение. Через
`friendly(e)` в session.ts текст предупреждения всплывал как error
прямо в форму входа.

**Почему так было.** SameSite=None нужен для cross-origin iframe на
**https** (Grok-превью поверх Vercel). На http — лишний, и больше
мешает, чем помогает.

**Правка.** Один и тот же принцип в обоих местах:

    sameSite: secure ? 'none' : 'lax'      // auth.ts (модуль-уровень)
    sameSite: isSecure() ? 'none' : 'lax'  // functions/auth.ts (на запрос)

На http — `SameSite=Lax` (тот же сайт, всё работает). На https —
`SameSite=None; Secure` (cross-origin iframe принимает).

**Проверка end-to-end.** `scripts/verify-signin-cookie.mjs` —
головой Chrome через DevTools Protocol открывает /login, переключает
на «Создать», заполняет уникальным логином, сабмитит, читает
`Set-Cookie` из `response.headers` (Chrome 115+ удалил
`Network.getResponseHeaders`, headers лежат прямо в `responseReceived`).
Без зависимостей: использует встроенный `WebSocket` из Node 22.
Прогон:

    set-cookie: chekagent.session_token=NRxPGaH14Q4KNfZ1ii13AhGWXqjWwUnz;
                Max-Age=5184000; Path=/; HttpOnly; SameSite=Lax
    COOKIE OK — SameSite=None без Secure не встретилось

**Регрессия.** `tsc --noEmit` чисто, `npm run build` 29.5 с,
`scripts/smoke-vercel.mjs` 11 роутов + 8 проверок документа → SMOKE OK.

## «Не получилось войти» при живом токене — getSessionUser в момент входа

Cookie починили, но вход всё равно падал общим «Не получилось войти».
Причём пользователь `vasya@chekagent.app` в базе был.

**Как нашли.** `scripts/repro-signin.mjs` (headless-Chrome + CDP) регистрирует
свежего пользователя, чистит cookie **и** localStorage, потом входит им же и
печатает тело ответа серверной функции. В теле:

    {"ok":true,"token":"DZLdrMELKrJCqDXksjSNp3bbPFpHalgB","user":null}

`user` = null. А в `login.tsx` стояло
`if (!res.ok || !res.user || !res.token) setError('Не получилось войти')` —
вход рубился при валидном токене.

**Корень.** `shape()` в `src/server/functions/auth.ts` делал
`const su = await getSessionUser()`. А `getSessionUser()` → `getToken()`
читает **заголовки входящего запроса** (bearer или cookie). В момент
входа/регистрации сессия только что создана: bearer ещё не существует
(клиент токена не видел), cookie только уезжает в ответе. → null →
профиль null → вход заблокирован.

**Правка.**
1. `src/server/session.ts`: ядро вынесли в `getSessionUserByToken(rawToken)`,
   `getSessionUser()` теперь `getSessionUserByToken(getToken())`.
2. `shape()` вызывает `getSessionUserByToken(token)` — по токену явно.
3. `login.tsx`: решают `ok` и `token`; отсутствие профиля вход не запирает,
   его догоняет `refresh()`.
4. `app-state.tsx`: `setSession(token, user: SessionUser | null)` и
   `setToken(token, u?.id ?? null)` — сессия без профиля допустима.

**Проверка.** `repro-signin.mjs` после правки:

    signIn → {"ok":true,"token":"NLFK1uQAvTFYn7tzBlwW0ECTEm2TVFwu",
              "user":{"id":"IENSxJSg…","name":"RP mtr1gj51","role":"user"}}
    страница: «Добрый день, RP mtr1gj51 · ЕЩЁ НА 23 ДНЯ · 45 000 ₽»

**Важно для repro-скриптов.** После signUp сессия живёт в двух местах —
cookie **и** localStorage (`chekagent-v7`, persist Zustand). Чтобы довести
до signIn, надо чистить оба: `Network.clearBrowserCookies` +
`Storage.clearDataForOrigin(origin, 'local_storage,session_storage,indexeddb')`.
Только cookie — мало, /login всё равно редиректит на меню по bearer.

**Регрессия.** `tsc --noEmit` чисто, `npm run build` 14 с, smoke 11 роутов
+ 8 проверок документа → SMOKE OK, cookie-чек OK, tick 12 проверок → TICK OK.

## «Функционала дальше нет» с кассами — не было Outlet

Список касс открывался, но клик по кассе оставлял тот же список: казалось,
что дальше семьи ничего нет.

**Причина.** `/groups` — родитель `/groups/$id`, но не рендерил `<Outlet/>`.
Все хуки в родителе уже вызваны, поэтому ранний return безопасен:

    const childActive = useRouterState({
      select: (s) => s.matches.some(
        (m) => m.routeId !== '/groups' && (m.routeId || '').startsWith('/groups')),
    })
    if (childActive) return <Outlet />

**Ловушка тестов: позиционная раскладка форм.** `FILL_SUBMIT` заполняет
инпуты **по порядку на странице**. На странице кассы первый input — зарплата,
поэтому `FILL_SUBMIT(['Аренда', 45000, 15])` писало «Аренда» в зарплату,
45000 — в название, 15 — в сумму, а день оставался дефолтным «1». Внешне
всё работало, только платёж назывался «45000».

Правильно — по placeholder: новый `FILL_BY([['Аренда','Аренда'], ['45000',45000],
['день',15]])` из `scripts/_cdp.mjs` ищет `input[placeholder="…"]` и сабмитит
`el.closest('form')`. Ещё там же `CLICK_TEXT`.

**Итог:** `verify-family.mjs` → FAMILY OK: платёж «Аренда» 45 000 ₽ 15 числа,
список «Хотим», чат, второй участник по коду, и главное — доли по зарплате
120 000 / 60 000 дают 30 000 и 15 000 с общего платежа 45 000 (2:1),
«поровну» после вступления второго пересчиталось в 22 500 на каждого.

### Установка на экран требует https
По `http://192.168.x.x` нет secure context: service worker не регистрируется,
значит ни пушей, ни «Установить приложение» (только ярлык).

Сделано:
- `npm run dev:https` — Vite с самоподписанным сертификатом. Включается по
  `npm_lifecycle_event === 'dev:https'` (работает и в PowerShell, и в bash,
  без cross-env) или `DEV_HTTPS=1`.
- Сертификат генерируется сам (openssl) в `.dev-cert/`, SAN включает текущий
  LAN-IP; сменился IP — пересобирается. Каталог в .gitignore.

  Без него Chrome не считает приложение устанавливаемым. Офлайн-кэша

- `src/server/auth.ts`: в dev в trustedOrigins добавляются все локальные
  IPv4 (`http://IP:8080`, `https://IP:8080`).
